# Cards

Флеш-картки для підготовки до співбесіди в НКЦПФР. Картки генеруються з файлу
`../Question/04. Відповіді на перелік питань НКЦПФР (Question.pdf).md`.

- **Фронтенд:** SolidJS + Vite + TypeScript
- **База даних і авторизація:** Firebase (Cloud Firestore + Authentication, email і пароль)
- **Android:** Capacitor

## Як це працює

- Після входу застосунок читає картки з колекції `nkcpfr_cards` і ваш прогрес з `nkcpfr_users/{uid}/progress`.
- Повторення інтервальне (спрощений SM-2). Оцінки: «Не знаю» (10 хв), «Важко», «Знаю», «Легко». Під кнопками видно, коли картка повернеться.
- Firestore зберігає дані на пристрої. Без мережі вчити можна: оцінки відправляться, коли з'явиться зв'язок. Лічильник ⟳ у шапці показує, скільки оцінок ще не відправлено.
- Кожен користувач бачить лише власний прогрес (правила у `firestore.rules`).
- **Статистика** за день, тиждень, місяць і рік: повторення, точність, нові картки, час навчання (з порівнянням з попереднім періодом), графік активності, крива росту засвоєного, розподіл відповідей, календар занять, серія днів поспіль, прогрес за розділами і найскладніші питання. Дані — один документ на день у `nkcpfr_users/{uid}/daily`. Відкрити одразу потрібний період: `#/stats?period=year`.
- Меню: нижня панель на телефоні, бічна — на широкому екрані. Під час навчання меню ховається.
- **Колоди та імпорт** (Профіль → Колоди, або кнопка «🗂️ Колода: …» на головній). Вбудована колода «Співбесіда НКЦПФР» + власні колоди, імпортовані зі структури як у Shelf:
  ```
  Моя колода/
  ├── deck.md                  # Назва колоди / author: … / description: …   (book.md теж підходить)
  ├── 01-Управління ризиками.md   # I. Назва розділу, далі картки:
  │                                ## Питання?
  │                                Відповідь (усе до наступного «##»)
  └── 02-…md
  ```
  Імпорт: ZIP, папка (на комп'ютері), вибрані `.md`-файли або перетягування у вікно. Перед збереженням показується, що розпізнано, і зауваження. Повторний імпорт з тією самою назвою оновлює колоду. Колоди зберігаються в `nkcpfr_users/{uid}/decks` (правило Firestore `nkcpfr_users/{uid}/{document=**}` уже це покриває).
  Шаблон для заповнення — папка `template/Моя колода` (і `Моя колода.zip`), або кнопка «Завантажити шаблон» у застосунку; оновити шаблон: `npm run template`. Експорт «Папка з розділами» має той самий формат — його можна відредагувати й імпортувати назад.
- **Експорт** (кнопка «↓ Експорт» на сторінці «Картки» або «Профіль → Експорт карток»): вибрані розділи у форматах «Папка з розділами» (ZIP: `README.md` зі змістом + окремий `.md` на кожен розділ), Друк/PDF, Word (.doc), Markdown, Excel/CSV та Anki, за бажанням — із вашим статусом по кожній картці. У браузері файл завантажується, на Android відкривається системне меню «Поділитися».
- Інтерфейс двомовний — українська й англійська, перемикач УКР / ENG на екрані входу та в «Профілі». Вибір запам'ятовується на пристрої. Картки (питання й відповіді) лишаються українською. Тексти інтерфейсу — у `src/lib/i18n.ts`.
- Якщо колекція карток порожня або недоступна, застосунок показує вбудовану копію.

## 1. Налаштування Firebase (один раз)

Можна взяти наявний проєкт Firebase або створити новий. Колекції мають префікс `nkcpfr_` і не перетинаються з даними інших застосунків. Але **користувачі Authentication спільні для всього проєкту**.

1. **Authentication → Sign-in method** → увімкніть **Email/Password**.
2. **Firestore Database** → створіть базу, якщо її ще немає.
3. **Firestore → Rules** → додайте правила з `firestore.rules`.
   ⚠️ Якщо проєкт уже використовує інший застосунок, **не замінюйте** наявні правила. Скопіюйте лише два блоки `match /nkcpfr_...` всередину існуючого `match /databases/{database}/documents { ... }` і натисніть Publish.
4. **Project settings → General → Your apps** → додайте **Web app** (якщо його ще немає) і скопіюйте значення з Config.
5. Скопіюйте `.env.example` у `.env` і впишіть `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`.
6. **Project settings → Service accounts → Generate new private key**. Збережіть файл як `service-account.json` у цій папці. Він потрібен лише для заливки карток, у застосунок не потрапляє і в git не комітиться. Тримайте його в секреті: з ним є повний доступ до проєкту.
7. Залийте картки:
   ```powershell
   npm run seed
   ```

## 2. Запуск у браузері

Найпростіше — двічі клацнути **`start-web.bat`**. Він сам встановить залежності (перший раз), запустить сервер і відкриє http://localhost:5173.

Або вручну:

```powershell
npm install
npm run dev
```

## 3. Оновлення карток після змін у файлі 04

```powershell
npm run seed
```

Скрипт перегенерує `src/data/cards.json`, оновить колекцію `nkcpfr_cards` і видалить картки, яких більше немає у файлі. Прогрес по решті карток зберігається.

## 4. Збірка для Android

Потрібні JDK 21 і Android SDK (`ANDROID_HOME`).

Найпростіше — двічі клацнути **`build-android.bat`**. Він перевірить оточення, збере APK і покладе його в папку `app` як `Cards_<дата>_<час>.apk`, потім відкриє папку. Попередні збірки з `app` видаляються — там завжди лише остання.

Або вручну:

```powershell
npm run android:apk
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Скопіюйте його на телефон і встановіть (дозвольте встановлення з невідомих джерел).

Параметри Firebase з `.env` вшиваються в застосунок під час збірки, тож після зміни `.env` APK треба перезібрати.

Відкрити проєкт в Android Studio (для підписаного релізу, емулятора тощо):

```powershell
npm run android:open
```

Після кожної зміни коду або карток: `npm run android:sync`.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make-icons.ps1
```
